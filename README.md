# Design Asset Extractor

把一张 AI 拼版图、海报或插画，拆成能重复使用的设计素材。

这是一个在 Codex 中使用的 Skill。你提供图片和处理要求，Codex 负责看图、找出素材并确定提取参数，Python 脚本负责批量提取和生成透明 PNG。结果经过原图、浅底和深底对照后再交付。

普通素材先用本地脚本处理，无法可靠提取的会留下人工任务和原因。需要遮挡补全、人像处理，或明确选择生成式修补时，才调用当前会话的内置图片工具。

## 最新更新 · 2026-10-01

这次主要减少流程里的重复工作：批量看图、复用发现计划，以及减少原图解码和哈希读取。

- A 路线的普通 matte/crop 素材通过自动质量检查（QC）后，会合并成 Contact Sheet 对照拼版。每项都有原裁切、浅底和深底，逐项判断后一次提交。看不清的素材再单独放大；人像、生成式结果和复杂分割仍逐项检查，自动 QC 不直接算作通过。
- 发现素材时，先看最长边默认 1024 像素的缩略图，需要时查看原图局部。脚本将坐标转换回原尺寸，最终从原图提取素材。
- 同一张图、同一个处理目标可以复用发现计划。原图、目标约束、缩略图尺寸或脚本版本变化后重新发现，也可以强制刷新。每次新输出仍要重新审核。
- 在解码预算内，build 只完整解码一次源图。同一命令内复用未改变文件的 SHA-256，最终 verify 仍重新读取全部交付文件。

已有几何样图的五个素材全部通过，输出像素与旧版一致。三次本地 build 的中位耗时约为 0.525 → 0.464 秒，完整原图解码次数从 7 次降到 1 次。本轮用一张拼版完成五项对照，27 个交付文件校验通过。计时只覆盖脚本阶段，模型发现和看图时间另计。

首次安装现在会运行五套离线检查。具体用法见 [效率接口](references/efficiency.md)，测试范围和耗时记录见 [效率验证记录](docs/efficiency-validation-2026-10-01.md)。

### 同日更新：人像抠图与上半身构图

人像模式支持抠图、按需补齐身体，并整理成 3:4 的透明上半身素材：

- 明确要求人像抠图时，简单背景先用本地方法，复杂背景或难处理的发丝可用内置图片工具。需要补齐肩部、胸部时，一并处理并输出透明人像。
- 默认头部实际轮廓面积约占画布 40%，按轮廓面积计算，不按头部高度或外接矩形计算。60% 只作补全阶段的参考，无需额外生成中间图。
- 优先保留头发、双肩和胸部上段。脚本保持人物比例，不拉伸或放大；画布容不下时降低头部占比，并记录实测值。
- 已有透明图直接保留 Alpha，无需新增模型依赖或下载模型。人像模式只在明确请求时开启，普通素材仍默认用脚本处理，最多 5 项并行。
- 原图、工具回图和最终构图分别保存，附头部蒙版、比例记录和输入哈希，也支持中断恢复。生成式处理会标注来源，并对照原图检查身份、五官和姿态；生成工具无法保证所有原始像素都保持不变。

人像更新时，自测、原工作流、并发和人像构图四套离线检查均已通过。人像部分使用的是合成轮廓，尚未用用户真实照片验证发丝、身份保持和身体补全效果。详见 [人像流程](references/portrait.md) 和 [验证记录](docs/portrait-validation-2026-10-01.md)。

人像模式可以这样用：

> 使用 `$design-asset-extractor` 抠出这个人的上半身，缺少肩膀或身体时先补齐。输出 3:4 透明 PNG，头部实际面积约占 40%，优先保证双肩和上半身完整，保持本人脸部和原姿态。

## 适合什么场景

- 从 AI 拼版图、海报或插画中整理可复用装饰素材
- 把渐变图形、箭头、圆环、卡片、插画主体拆成透明 PNG
- 按需求补全主体被轻度遮挡的部分
- 抠出人像，补齐缺少的肩部、胸部，整理成透明上半身素材
- 将复杂透明、反射或严重缺失的对象整理成人工任务

## 在 Codex 中使用

安装后，把一张图片或一个图片文件夹交给 Codex，说明你想提取什么。例如：

> 使用 `$design-asset-extractor` 看图识别素材，用本地脚本批量提取，最多 5 个一起处理，检查后交付透明 PNG。

坐标、JSON 和蒙版参数由 Codex 准备，你不用手写。它负责识别素材、确定边界框（bbox）、采样背景颜色，并在需要时标记前景和背景点，脚本再按计划提取。

当前本地方法包括均匀背景分离（matte）、完整矩形照片裁切（crop），以及浅色背景上深色主体的分割（bright-background）。crop 保留照片内部背景，只让外围透明。本地方法没有通用语义分割模型，也不需要额外下载模型。

默认使用 `build --workers 5 --processing local-first`，按实际素材数量并行处理，最多 5 项。你也可以说“最多 3 个一起处理”，或通过 `--workers 3` 调整上限，参数接受正整数。

宿主支持 subagent 时，Codex 会把发现和复核任务分给子 agent，一项完成后继续下一项；只有一项时直接处理。子 agent 默认沿用主 agent 的模型，可用数量取决于宿主。本地线程池单独运行，即使 agent 数量较少，脚本也可以按配置批量提取。

## 处理原则

1. 保留源图、提取坐标和源文件哈希，方便核对来源。
2. A 路线按模型给出的参数提取原像素，先检查结果，再添加透明外边距。普通素材默认提取失败后进入 C；已有透明人像保留原 Alpha。
3. B/complete 处理明确要求的补全，人像模式也允许必要的 B/extract。每个生成式素材最多请求两次；一般生成式分离或修补需要明确选择 `--processing builtin-repair`。
4. C 路线保存人工任务和处理原因。
5. Alpha、边缘和视觉检查均通过后，透明 PNG 才能交付。

主 agent 汇总发现计划并运行脚本，各 worker 负责分配到的素材或审核批次，共享记录通过文件锁保护。生成结果按素材 ID 和尝试编号导入；请求结果不明时保留原任务、占用名额并等待恢复，不重复发送。

复杂透明、反射，以及本地方法无法可靠分离的复杂背景会转人工处理。具体能否提取，要看原图和实际输出。

内置图片工具没有提供模型选择参数，运行记录只填写工具实际返回的模型信息，不预先标成 Images 2.5 或其他型号。遮挡补全会生成原图中看不到的部分，并标注为生成式处理。

## 实测结果

2026-09-30 的默认路线实测中，几何原图的 5 个素材全部由本地脚本提取，并通过深浅背景复核，图片生成调用为 0。当次 build 约 0.94 秒，模型识别和视觉复核时间另计。并发、结果关联与兼容性测试见 [2026-09-30 验证报告](docs/local-first-parallel-validation-2026-09-30.md)；本次效率更新的对照计时见上方更新说明。

公开示例也保留了早期提取结果和内置图片工具案例，其中部分素材使用过生成式处理：

- 几何素材图：14 个透明 PNG 输出通过视觉复核，包含渐变圆、箭头、圆环、阶梯等。
- 贝壳案例：真实内置图片工具调用得到 1274 × 1235 透明 PNG，并完成原图、浅底、深底对照。

贝壳被遮挡的部分由 AI 补全。海龟的工具调用曾中断，记录为阻塞；透明气泡则保留为人工任务。验证报告中保留了这些未完成和未通过的情况。

## 运行验证

首次在仓库根目录运行（Python 3.12；自动创建隔离环境、安装固定依赖并测试）：

```powershell
./scripts/bootstrap.ps1
```

后续命令使用 `.venv/Scripts/python.exe`。Codex 按 SKILL.md 看图、保存或复用发现计划，脚本批量提取，再通过 Contact Sheet 或单项预览对照原图和深浅底。需要生成式补全时，按已确认的处理要求调用工具。

`status` 返回下一步操作，`review-sheet/review-batch` 用于批量审核。任务完成后，`finalize` 生成交付清单和哈希索引；复制任务目录后，可用 `verify` 检查文件是否完整。只有 PASS 算作可交付素材，人工项附任务图和原因，未解决的阻塞会单独报告。

生成一套可检查的离线合成样例：

```powershell
./.venv/Scripts/python.exe scripts/test_workflow.py --output outputs/offline-demo
./.venv/Scripts/python.exe scripts/test_parallel.py --output outputs/parallel-demo
./.venv/Scripts/python.exe scripts/asset_job.py verify --job outputs/offline-demo/synthetic-workflow
```

这些合成样例用于验证处理流程，不调用图片模型。固定库版本、计划、来源记录、已保存的回图和素材都可以留存核对；重新请求生成模型时，像素结果可能不同。依赖和完整命令见 [执行接口](references/workflow.md)。

本项目不包含用户原始图片、API Key、Codex 缓存或临时任务目录。
