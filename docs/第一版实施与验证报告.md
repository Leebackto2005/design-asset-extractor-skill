# Design Asset Extractor 第一版实施与验证报告

日期：2026 年 9 月 10 日
项目状态：本地内部原型，已完成平底素材拼版的首次样图验证
报告依据：本次实现、两轮样图运行记录、最终 manifest、输出文件及视觉复核记录

## 1. 结论

第一版已实现“看图定位与分流 → 本地去背景 → 深浅底复核 → 通过后导出”的基本流程，并安装到本机 Skills 目录。

以用户提供的图 2 为主要验证样本，共处理 15 个素材组合：14 个通过 Codex 的本轮视觉复核，1 个因叶枝连接处浅色残留被拒绝放行。另外，使用图 1 的扇贝验证修补包输出，使用图 3 的玻璃瓶与水流验证人工分流。

当前结果支持继续开展小范围设计师试用；尚不足以认定原方案的 V2 Demo 全部完成，也不足以证明业务可用率、自动覆盖率或节省时间达标。

## 2. 本轮范围与产品取舍

第一版优先处理近似均匀背景、主体完整、不透明的素材拼版。默认保留可复用组合，例如花与叶片、重叠圆、点阵、线圈和彩带与太阳；只有明确要求独立零件时才继续细拆。

| 样本 | 本轮实际用途 | 未覆盖范围 |
|---|---|---|
| 图 1：海洋素材拼版 | 选取被叶片遮挡的扇贝，制作独立补全任务示例 | 没有实际提取整张图的海龟、太阳、海星等全部候选 |
| 图 2：几何素材拼版 | 15 个组合素材的实际去背景与视觉复核 | 不将重叠圆和彩带太阳拆成独立隐藏图层 |
| 图 3：完整广告画面 | 选取玻璃瓶与水流，记录人工处理原因 | 没有执行玻璃、水流的透明重建，也没有全量提取画面 |

本轮没有开发 WebUI、网页自动化、大型分割模型接入、云端服务或多 Agent。修补操作仍由用户在网页完成。

## 3. 已实现的能力

| 能力 | 实现情况与边界 |
|---|---|
| 看图与候选定位 | 由 Codex 查看图片、确定组合、填写框选位置；脚本不自动发现语义对象 |
| A/B/C 分流 | 由 Codex 决定 AUTO、IMAGE2 或 MANUAL，并记录原因 |
| 平底去背景 | 背景采样、连通区域处理、内部空隙种子、前景选择与软边处理 |
| 排除相邻素材 | 用前景点选中目标连通区域；无法分离已经粘连的对象 |
| 透明输出 | 保存 RGBA PNG 和 Alpha 蒙版，保留原始裁切像素尺寸 |
| 质量检查 | 检查非空主体、真实透明区域、主体是否触及裁切边界；生成原图/浅底/深底预览 |
| 复核后放行 | 初始结果进入 REVIEW；记录视觉结论后才进入 assets，拒绝结果进入 rejected |
| 网页修补包 | 裁切图、原图关联、具体中文修补说明；没有生成无依据的修补蒙版 |
| 修补回流 | 按素材 ID 接收首次回图，记录来源与生成式修补标记，重新处理与复核；仅做过合成样本程序验证 |
| 多源任务 | 同一计划支持多张图片，逐候选处理和记录；本次任务包含三张来源图 |
| 可追溯记录 | 记录源文件路径与 SHA-256、候选坐标、路线、状态、复核说明及输出 SHA-256 |

实现使用当前环境已有的 Pillow 12.2.0、NumPy 2.4.4 和 OpenCV 5.0.0，没有增加模型下载或远端 API 调用。

### 4.2 未放行与分流原因

**绿色叶枝：**深底预览中，叶片与茎连接处仍有浅色碎片或背景残留。已保留结果与拒绝说明，不计入 assets。

**扇贝：**原图部分壳体被叶片遮挡。提取可见轮廓无法获得完整独立扇贝，修补包明确要求补全被遮挡部分，并标明补全部分属于生成内容。该任务是可选独立补全示例，不代表默认要把所有组合拆散。

**玻璃瓶与水流：**透明主体包含原场景的透射与反射，并与周围物体交叠。仅去除外围背景不能保证换底后自然，因此转人工。

## 5. 实际发现的问题与修正

| 问题 | 证据与影响 | 本轮处理 |
|---|---|---|
| 矩形裁切带入旁边素材 | 圆、箭头、自由形状等裁切框包含邻近元素片段 | 增加目标前景连通区域选择，保留指定组合 |
| 深底下出现浅色边 | 首轮黑色点阵、细线等预览可见背景色边缘 | 使用邻近不透明前景估计边缘覆盖率并去除混入的背景色 |
| 圆环裁切过窄 | 首轮主体接触裁切左边界，触发 ERROR | 扩大裁切范围，第二轮重新处理并通过检查 |
| 叶枝内部浅色残留 | 第二轮深底预览仍可见残留 | 拒绝放行，保留人工处理依据 |

首轮 run-01 保留，未用最终结果覆盖首轮失败记录。第二轮 run-02 的 build 退出码为 0。

## 7. 原方案 KPI 对照

| 原方案目标 | 本轮能否判定 | 仍缺少什么 |
|---|---|---|
| 设计师直接可用率 ≥85% | 不能 | 设计师逐项确认实际可用性 |
| 自动覆盖率 ≥50% | 不能 | 对全部有效素材进行独立标注，包含漏发现素材 |
| 错误自动化率 ≤10% | 不能 | 对已放行结果的独立复查，确认是否存在错误放行 |
| 人工时间节省 ≥50% | 不能 | 同类任务的人工基线及使用 Skill 后的完整人工耗时 |
| 20 张历史素材图验收 | 未完成 | 更多真实公司工作样本及统一验收记录 |

如果“错误自动化率”定义为不可用输出占全部输出的比例，则 ≤10% 对应可用率 ≥90%。正式试用前应统一指标定义，避免与 ≥85% 的目标口径混淆。

## 8. 下一步建议

1. **先让设计师试用这 14 个 PNG。** 记录哪些能直接用、哪些需要修边，以及实际使用尺寸，不先增加功能。
2. **完成一次真实修补回流。** 用已有扇贝修补包在网页生成结果，交回后验证匹配、去背景、风格和透明边缘。
3. **补充 5～10 张同类真实拼版。** 同时记录 Codex 定位和复核所需的人工作业时间，避免只统计脚本耗时。
4. **再决定是否接分割模型。** 当平底工具的覆盖范围已经明确，且设计师确有复杂背景需求时，再用实际失败样本评估收益。

建议维持“可用率优先”的门槛：自动处理数量可以暂时少，明显有问题的结果继续拒绝放行。
